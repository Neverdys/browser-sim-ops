## 0.2.1 中断与资源清理复审（2026-11-01，基线 fac5d2d）

独立审查用替身复现了三项问题，本轮修复：

| 问题 | 修复 | 回归（`tests/interrupt.test.mjs`） |
|---|---|---|
| 读计划、`/health` 探测、截图等阶段收到 SIGINT/SIGTERM 时进程被直接终止，锁残留，结果和运行记录丢失 | 计划在加锁前读取；持锁期间整个命令捕获信号，第一次按暂停处理并正常释放；第二次立即退出、只移除本进程的锁、按结果未知报告 | 读计划、探测、截图、长输入中断；二次中断 |
| 长文本输入、滑动期间不响应暂停（实测暂停后又发出约 3950 条按键消息，9 秒后才停） | 每 16 个字符、每个滑动移动点检查暂停；滑动停下先抬起手指；`type/key/button` 发送前也检查 | 暂停后最多再发一批；滑动最后一条为抬起；提交输入中被中断报 unknown |
| `stop`/`start` 只按 PID 判断 helper，PID 被复用时可能向无关进程发 SIGTERM | 发信号前用 `ps` 核对命令参数和已记录启动时间；PID 不存在或启动时间确实不同才视为已退出；无法确认时保留 lease | 复用 PID 不发信号、`ps` 失败保留 lease、自己的 helper 照常停止、残留状态文件不当作 helper |

另新增 `unlock`（同一 owner、持锁进程确认已退出才移除，不按时长接管），`run` 在缺少全局 WebSocket 的 Node 上加锁前明确停止；补充 `actions`/`actions_attempted` 含义、中断语义和升级说明。

后续复审发现原先的旁路 rename 仍存在解锁竞争，命令行子串匹配会误认相似路径，且缺失启动时间或改变包装命令环境变量可能错误释放 lease。本轮补充修复：

- 获取、解锁和释放共用一个短时同步门闩，移除旁路 rename；正常结束和第二次信号均核对本次 token 后释放。硬中断遗留门闩时停止，人工确认后处理，不自动接管。
- 所有 `ps` 固定 `LC_ALL=C`、`TZ=UTC0`。已记录的启动时间不可读或不可比时停止；同一存活实例身份不明时保留 lease。
- helper 路径仅在可执行或支持的解释器脚本位置识别，UDID 限定完整参数；`tail -f /tmp/serve-sim` 和其他脚本的数据参数均不会被当作 helper；启动命令路径存入现有 lease，环境变量变化不丢失清理责任；失败启动记录新 helper 的时间。
- 保留部分输入暂停、提交结果 unknown、第二次中断先抬起手指的行为。

新增针对性回归先在修复前失败、修复后通过；并发用独立 Node 子进程和真实临时目录确定性调度，覆盖检查期间另一个 unlock/acquire 进入、替换锁 token、SIGKILL 遗留门闩。CLI 中断用真实子进程信号，helper/网络/设备调用均为替身，测试后清理子进程和临时目录。可运行 `npm test` 复现。

**仍未验证**：真实 WebSocket 在断线不关闭时的缓冲行为、serve-sim 收到 SIGTERM 后是否删除状态文件、Node 22.x 实机运行、真实设备上的暂停延迟。替身测试只证明本工具在这些阶段的控制流和清理顺序。
